Multi-Physics Simulation Guide

This guide provides information on using the LENR Simulation API for running coupled multi-physics simulations.

Introduction to Multi-Physics Coupling

Multi-physics coupling allows the simulation of complex physical systems where different physical phenomena interact with each other. In LENR (Low Energy Nuclear Reaction) simulations, this typically involves coupling nuclear reactions with thermal effects.

The key components of our multi-physics framework are:

  • Physics Domains: Self-contained modules that simulate specific physical phenomena
  • Domain Couplers: Components that manage data exchange between domains
  • Domain Manager: Coordinates all domains and manages time stepping

Available Physics Domains

Thermal Domain

The thermal domain simulates heat transfer using the heat diffusion equation:

∂T/∂t = α∇²T + Q/(ρcp)

Where:

  • T is temperature
  • α is thermal diffusivity (k/(ρcp))
  • Q is the heat source from nuclear reactions
  • ρ is material density
  • cp is heat capacity

Nuclear Domain

The nuclear domain simulates nuclear reactions and calculates reaction rates and energy production. It supports various reactions and enhancement mechanisms:

  • Reactions: d-d, p-B11, d-t, etc.
  • Enhancement Mechanisms: electron screening, coherent tunneling, etc.

Running a Coupled Simulation via the API

1. Start a Simulation

Send a POST request to start a new simulation:

POST /api/multi-physics/simulations

{
  "domain_size": [0.01, 0.01, 0.01],
  "resolution": [20, 20, 20],
  "simulation_time": 0.01,
  "time_step": 1e-6,
  "reactions": ["d-d"],
  "mechanisms": ["electron_screening", "coherent_tunneling"],
  "initial_temperature": 300.0,
  "species_densities": {"d": 1.0e28},
  "thermal_conductivity": 10.0,
  "heat_capacity": 500.0,
  "material_density": 1000.0
}

This will return a simulation ID that you can use to check the status and retrieve results:

{
  "simulation_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "status": "pending",
  "message": "Simulation started in the background",
  "estimated_duration": 10.0
}

2. Check Simulation Status

Poll the status endpoint to check the progress:

GET /api/multi-physics/simulations/3fa85f64-5717-4562-b3fc-2c963f66afa6/status

3. Retrieve Results

Once the simulation is complete, retrieve the results:

GET /api/multi-physics/simulations/3fa85f64-5717-4562-b3fc-2c963f66afa6/results

Parameter Configuration

Domain Size and Resolution

The domain_size parameter specifies the physical dimensions of the simulation domain in meters. The resolution parameter specifies the number of grid points in each dimension.

Note: Higher resolution provides more accurate results but requires more computation time. A good starting point is 20×20×20 for quick tests.

Simulation Time and Time Step

The simulation_time parameter specifies the total physical time to simulate in seconds. The time_step parameter specifies the time step size in seconds.

Warning: Very small time steps can significantly increase computation time. The API automatically adjusts time steps for stability, but starting with a reasonable value is recommended.

Reactions and Mechanisms

The reactions parameter is an array of reaction names to simulate. Supported reactions include:

  • d-d: Deuterium-Deuterium fusion
  • d-t: Deuterium-Tritium fusion
  • p-B11: Proton-Boron fusion

The mechanisms parameter is an array of enhancement mechanisms to include. Supported mechanisms include:

  • electron_screening: Enhanced tunneling due to electron screening
  • coherent_tunneling: Enhanced tunneling due to coherent effects
  • lattice_vibration: Enhanced tunneling due to lattice vibrations

Best Practices

  • Start with lower resolutions (10×10×10) for quick tests before running high-resolution simulations
  • Use appropriate physical dimensions (typically mm to cm scale for LENR systems)
  • Choose time steps that balance accuracy and performance
  • Delete completed simulations when they are no longer needed to free up server resources

Example Workflow

# 1. Start a new simulation
curl -X POST http://localhost:8000/api/multi-physics/simulations \
  -H "Content-Type: application/json" \
  -d '{
    "domain_size": [0.01, 0.01, 0.01],
    "resolution": [20, 20, 20],
    "simulation_time": 0.01,
    "time_step": 1e-6,
    "reactions": ["d-d"],
    "mechanisms": ["electron_screening"],
    "initial_temperature": 300.0,
    "species_densities": {"d": 1.0e28},
    "thermal_conductivity": 10.0,
    "heat_capacity": 500.0,
    "material_density": 1000.0
  }'

# 2. Check status periodically
curl -X GET http://localhost:8000/api/multi-physics/simulations/SIMULATION_ID/status

# 3. Retrieve results when complete
curl -X GET http://localhost:8000/api/multi-physics/simulations/SIMULATION_ID/results

# 4. Clean up when done
curl -X DELETE http://localhost:8000/api/multi-physics/simulations/SIMULATION_ID

Troubleshooting

Issue Possible Cause Solution
Simulation fails to start Invalid parameters or server resources Check request format and parameter values
Simulation takes too long Resolution too high or time step too small Reduce resolution or increase time step size
Results show NaN values Numerical instability Reduce time step or adjust physical parameters

For more information, refer to the API Documentation or contact support.
